# InkOS RU: план локализации

Статус: проектирование. Базовая ветка `master` синхронизируется с `Narcooo/inkos`; изменения выполняются в отдельных ветках.

## Принципы

- Разделять язык интерфейса (`uiLocale`) и язык произведения (`contentLanguage`).
- Сохранять обратную совместимость файлов и существующих проектов `zh`/`en`.
- Не менять агентный Pi harness, контракты подтверждений и атомарную запись без необходимости.
- Для всех этапов предусмотреть тесты на русском языке; не выдавать генерацию текста за проверенное качество без реального запуска модели.

## Этап 1. Поддержка ru в ядре

1. Расширить модели книги, проекта и состояния произведения: `zh | en | ru`.
2. Ввести общий тип языка, убрать молчаливое преобразование `ru` в `zh` в CLI и Studio.
3. Добавить `ru_words` и подсчет кириллических слов по Unicode с тестами на дефисы, числа, сокращения, Markdown и смешанный текст.
4. Добавить русский режим инструкций Writer, Planner, Reviewer и связанных производственных методов.
5. Проверить создание, запись, повторное чтение, редактуру, восстановление и экспорт русскоязычной книги.

## Этап 2. Методика русской прозы

- Русские `SKILL.md`: длинная проза, короткий рассказ, литературная редактура, стилистическая очистка, сценарии и перевод.
- Правила: падежи, согласование, естественные диалоги, пунктуация, обращение с «ё», непреднамеренные кальки, шаблонные ИИ-конструкции.
- Правки сохраняют авторский голос и факты произведения.

## Этап 3. Интерфейс

- Вынести строки Studio из двуязычных `tr(zh, en)` в расширяемые словари `zh/en/ru`.
- Перевести Studio, CLI, TUI, ошибки, подсказки и первоначальную настройку.
- Русский язык интерфейса не должен принудительно задавать язык книги.

## Этап 4. Приёмка

- `pnpm install`, `pnpm typecheck`, `pnpm test`, `pnpm build` без регрессий на Node.js 22/24.
- Контрольный русский проект: не менее трёх последовательных глав, сохранение канона, редактура и экспорт.
- Измерение корректности подсчёта слов и ручная оценка качества художественного текста.
- Обновление README.ru.md и инструкций для Windows 11.

## Риски

- Жёсткие `zh/en` ветвления встречаются в моделях, промптах, Studio и TUI: требуется сквозное изменение.
- Текущий английский счётчик использует латинский regex и не считает кириллицу.
- Значение `ru` без полного исправления маршрутов может молча превращаться в `zh`.
- Русский язык переводов уже доступен; это не равно русской поддержке полного конвейера сочинения.
