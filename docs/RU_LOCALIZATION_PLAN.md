# InkOS RU — мастер-план русификации и сопровождения (v2.0)

> Статус: **реализация InkOS RU активно ведётся; основные сквозные автоматические сценарии реализованы, стабильный выпуск заблокирован до реальной LLM-приёмки и итогового аудита**.
> Дата аудита: 2026-10-24. Репозиторий: [perejaslav/inkos-ru](https://github.com/perejaslav/inkos-ru).
> Основа: [Narcooo/inkos](https://github.com/Narcooo/inkos), ветка `master`; рабочая ветка: `feat/russian-localization`.
> Текущий план заменяет первоначальный краткий `RU_LOCALIZATION_PLAN.md`; история исходного текста сохранена в Git (`58e45b9c`).

## 1. Цель и определение готовности

**Цель:** поддержка русского языка как первого класса в InkOS 2.x, без поломки китайского и английского сценариев: от создания произведения, долгосрочной памяти и работы агента до редактуры, интерактивных сюжетов, восстановления и экспорта.

**Готовый InkOS RU** должен:
1. Позволять независимо выбрать русский интерфейс и русский/английский/китайский язык *отдельного произведения*.
2. Писать и редактировать русские романы, рассказы, сценарии, раскадровки, фанфики, продолжения, интерактивные истории и переводить документы на/с русского.
3. Корректно учитывать русские слова и границы глав, не пересчитывать кириллицу как китайские символы или ноль английских слов.
4. Хранить и восстанавливать русские тексты, канон, историю, прогнозы, состояния и сессии без скрытого переключения на `zh`.
5. Сохранять язык и Unicode во всех форматах экспорта, прежде всего Markdown/TXT/EPUB; выдавать валидный `lang` для EPUB.
6. Предоставлять русскоязычные Studio, CLI, TUI, статусы, ошибки, инструкции, подсказки и документацию.
7. Работать с пользовательскими OpenAI-совместимыми и поддерживаемыми локальными провайдерами в пределах исходного функционала.
8. Сохранять работоспособность `zh/en` и гарантии исходного Pi Agent Harness (подтверждения, право на запись, атомарные коммиты, восстановление).

**За границами первого стабильного выпуска:** обучение собственной LLM, машинный «объективный» рейтинг художественного качества, перевод всех сторонних материалов без проверки лицензий, публикация произведений на внешние литературные платформы, новые платные сервисы, автоматическая отправка рукописей в облако. Не менять устройство агентного ядра без воспроизводимой причины.

## 2. Проверенная отправная точка

Обнаружено в текущих исходниках (это карта риска, а **не** полный реестр найденных вызовов):
- Около **96 файлов** удовлетворяют широкому поиску типизированных языковых развилок, проверок или счётчиков. Это оценка для аудита; цифру не считать списком обязательных изменений.
- `packages/core/src/models/book.ts`, `models/project.ts`, `models/runtime-state.ts` — строгие `zh/en` схемы.
- `packages/core/src/models/length-governance.ts` — только `zh_chars` и `en_words`; `utils/length-metrics.ts` считает английские слова латинским regex `[A-Za-z0-9]` и не считает кириллицу.
- `packages/studio/src/api/book-create.ts`, `pages/BookCreate.tsx`, `api/server.ts` и `packages/cli/src/commands/init.ts` способны без ошибки подменять нераспознанный язык на `zh`.
- `packages/core/src/interaction/export-artifact.ts` формирует EPUB с меткой `zh-CN` для неанглийского романа.
- `packages/studio/src/hooks/use-i18n.ts` — около 315 пар `zh/en`, есть встроенный `tr(zh,en)` (`lib/app-language.ts`), строки в страницах, сервере, CLI и TUI.
- Ограничения в `forecast`, `play`, `interactive-film`, `pipeline`, `interaction`, `harness`, `short-fiction`, сохранённых сессиях и действиях.
- `packages/core/src/retrieval/local-search.ts` уже использует Unicode/`Intl.Segmenter`, но качество русскоязычного поиска (падежи, `е/ё`, составные слова) отдельно не измерено.
- Русский есть в списке переводов (`TranslationManager.tsx`), а схемы проекта перевода разрешают названия языков-строки; это **не равно** русской поддержке конвейера сочинения.
- В `packages/core/skills/` на момент проверки фактически обнаружено **20 папок** Skills — учитывать актуальное дерево, а не устаревшее число из README.
- `.github/workflows/release.yml` предусматривает публикацию upstream-пакетов `@actalk/*` по тегам `v*`. Форк не должен случайно запускать чужой релиз.
- GitHub CI уже тестирует Node 22/24 на Windows и Linux. Для локального воспроизводимого окружения зафиксировать ожидаемую версию pnpm (CI использует 9): глобальный pnpm 11 без такой фиксации может менять lockfile/поведение.
- `docs/*` указан в `.gitignore`; данный файл уже отслеживается Git, новые документы будут требовать явного исключения или `git add -f`.

Перед кодовыми изменениями снять *фактическую* базовую статистику: точный SHA upstream, версии инструментария, список тестов и их PASS/FAIL/SKIP, состояние `pnpm-lock.yaml`, существующие known failures. Не приписывать исходникам прохождение тестов без запуска.

## 3. Архитектурные решения (обязательные)

### ADR-01. Разные языковые оси
- `uiLocale`: язык интерфейса (`zh-CN`, `en`, `ru-RU`); хранить как **настройку отображения**, не как язык книги.
- `contentLanguage`: язык конкретного произведения (`zh`, `en`, `ru`). В прежних структурах `language` остаётся совместимым полем до контролируемой миграции; не переименовывать сразу все файлы пользователя.
- `responseLanguage`: язык текущего ответа агента (явный запрос пользователя имеет приоритет, затем предпочтение интерфейса/сессии). Не должен переписывать канон на другом языке.
- Для переводов сохранять независимые `sourceLanguage` и `targetLanguage`, не сужая их до трёх языков.
- Общий модуль нормализации BCP 47: `ru`/`ru-RU` → `ru` в книге; для UI → `ru-RU`; `en-US` → `en`; `zh-CN` → `zh`. Неизвестный код не превращать в `zh`: вернуть понятную ошибку с разрешёнными вариантами.
- В typed action/tool contracts внутренние названия ключей и коды ошибок не переводить; локализуется только представление пользователю.

### ADR-02. Русский подсчёт длины
- Добавить `ru_words` в `LengthCountingModeSchema`, `LengthSpec`, телеметрию, UI и экспорт. Не изменять значения сохранённых `zh_chars` и `en_words`.
- Учитывать **слова исходного художественного текста**, очищенного от структурного Markdown (frontmatter/заголовки/служебные поля), используя Unicode-aware сегментацию (кандидат: `Intl.Segmenter('ru', {granularity:'word'})`).
- Зафиксировать письменную политику: сложные слова через дефис, частицы, сокращения, числа, латиница в русском тексте, переносы, апострофы, тире в диалогах, NBSP, `ё` и знак ударения. Не считать разнородные символы «по ощущениям».
- Длина «целевой объём» и «жёсткие ограничения автора» различаются; не дополнять текст бессмысленно только ради числа. При расхождении данных текста/телеметрии — сигнал и безопасная пересинхронизация.

### ADR-03. Строки и русский язык агента
- Языковые системные инструкции хранить в прозрачных шаблонах/локализованных ресурсах с **одинаковыми требованиями к действиям**; не заменять безопасность свободным переводом.
- Общая функция локализации с явным `ru` и типовой проверкой полноты словарей; переходный слой для старых вызовов `tr(zh,en)` допускается лишь при явном `en`-fallback на UI, никогда — `zh`-fallback для русского контента.
- Профессиональные Skills применяются к действующим задачам, а не просто потому, что пользователь выбрал русский UI. Не дублировать логику pi-agent.
- Markdown/JSON, внутренние идентификаторы артефактов, пути, вызовы tools и структура `ActionResult` остаются машинно стабильными.

### ADR-04. Обратная совместимость и безопасность
- Существующие книги `zh/en`, контракты `WorkManifest`, `book.json`, сеансы, `lengthTelemetry`, индексы и экспорт читаются без принудительной переписи.
- Для изменяемых версий схем — явная версия формата, `dry-run` миграции, сохранение полного снимка и проверенный откат; использовать существующие `inkos work migrate`/backup/restore только после проверки их семантики.
- Изменения в `.inkos`/`books`/`works` с реальными пользовательскими данными запрещены при разработке без явно выбранной тестовой копии.
- Атомарное сохранение, блокировки работы и политика подтверждений остаются без регрессий.

## 4. Сквозной реестр областей (Coverage Matrix)

Для **каждого** указанного блока на этапе 0 заполнить: точки входа → схема/хранилище → prompt/Skill → счётчик → локализация → экспорт → тесты → статус (not started / partial / verified / blocked).

| Область | Ключевые модули | Минимальный сквозной критерий |
|---|---|---|
| Создание Work/книги | `models/project.ts`, `models/book.ts`, `harness/tools/work-creation.ts`, `interaction/action-envelope.ts`, Studio/API, CLI | `ru` доходит до хранилища без преобразования в `zh` |
| Длинная проза | `agents/architect.ts`, `planner.ts`, `writer.ts`, `writer-prompts.ts`, `reviser.ts`, `pipeline/*` | 3 главы, редактура, канон, смысловые связи и корректная телеметрия |
| Короткая проза | `prompts/short-fiction.ts`, `pipeline/short-*`, `short-production-state.ts` | Создание, пересмотр, вывод и продолжение на русском |
| Сценарии и раскадровки | `pipeline/script-storyboard-runner.ts`, Skills | Естественный русский текст, связи между сценами, экспорт |
| Play и интерактивные миры | `play/*`, `models/play.ts` | Состояние, варианты выбора, свободный ввод, сохранение/возобновление по-русски |
| Интерактивное кино | `interactive-film/*`, `agent/film-authoring-tools.ts` | Русские узлы/финалы, граф, валидация и экспорт |
| Фанфик / продолжение / ответвление / подражание | `agents/import-context.ts`, Skill-пакеты, импорт глав | Сохранение канона, собственных имён, авторских ограничений, метаданных |
| Прогноз сюжета | `forecast/*` | 2–5 ветвей, выбор не меняет канон, stale-пометки работают |
| Редактура / стиль / очистка | `agents/*review*`, `reviser.ts`, `skills/*` | Проверка на русском, доказательные замечания, без поломки сюжета |
| Память, контекст и поиск | `state/*`, `retrieval/*`, `references/*` | Реальный поиск по русским именам и терминам, воспроизводимость ссылок |
| Сессии / агент | `interaction/session-transcript-*`, `harness/*`, `agent/*` | `ru` в восстановлении сеансов и typed actions, подтверждения сохранены |
| Перевод | `translation/*`, Studio Translation | Перевод в/из русского, глоссарий, дозапуск, сохранение и экспорт |

| Интеграция моделей | `llm/*`, Studio settings, CLI config | Провайдер не меняется от локали, модель может выдать кириллицу, секреты защищены |
| Сборка / поставка | `packages/*/package.json`, `pnpm-lock.yaml`, `.github/workflows/*` | Сборка Win/Linux, безопасные имена/теги пакетов и публикация только по разрешению |

## 5. Дорожная карта и контрольные точки

Каждый этап заканчивается отдельным PR/коммитом (или небольшими PR в рамках этапа), набором доказательств и статусом Gate. **Ни один этап не закрывать одним успешным `typecheck`.**

### Этап 0 — Базовый аудит и безопасность репозитория (P0)

**Работы:**
- [ ] Зафиксировать upstream SHA, ветку, дерево и версии Node/pnpm; зафиксировать исходные тесты: `build`, `typecheck`, `test`, `test:flows` и доступные E2E без изменения среды пользователя.
- [ ] Составить `LANGUAGE_COVERAGE.md` с точными файлами, режимами и небезопасными `if/else`; классифицировать: строгий тип, сериализация, контент, отображение, временный fallback.
- [ ] Инвентаризировать 20 текущих встроенных Skill-каталогов, существующие русские элементы переводчика и контрактов.
- [ ] Создать воспроизводимые **искусственные** тестовые проекты `zh/en`, эталонные заголовки, главы, сессии и варианты EPUB; никаких пользовательских рукописей.
- [ ] Зафиксировать `AGPL-3.0-only`, атрибуцию, правила сохранения copyright; проверить лицензионные совместимости новых зависимостей и корпуса примеров.
- [ ] Защитить fork release: исключить случайную публикацию `@actalk/*` из `release.yml`, пока не выбраны новые package names и права на npm; оставить CI тестов.
- [ ] Настроить обработку папки `docs/` в Git, запись решений ADR, минимальную матрицу CI Windows/Linux × Node 22/24 × pnpm 9.
- [ ] Создать `ISSUES_BACKLOG.md` с зависимостями, рисками и ссылками на тесты.

**Gate 0:** baseline записан (включая неудачные/пропущенные тесты), все опасные релизные действия заблокированы, матрица покрытия составлена. Разработку не начинать «на глаз» по одному типу `language`.

### Этап 1 — Ядро русского языка и сохранение данных (P0; зависит от 0)

**Работы:**
- [ ] Общие typed-схемы языков + нормализация; фиксированный приоритет пользовательского запроса, языка Work/книги и UI; обработка неподдерживаемой локали — явная ошибка.
- [ ] Согласованно расширить `ProjectConfig`, `BookConfig`, `RuntimeState`, `ActionEnvelope`, Work/Profile, transcript, forecast/Play/short-state и сериализаторы. Не изменять машинные ID инструментов.
- [ ] `ru_words`; согласованное измерение у Writer, Planner, Reviewer, Reviser, Runner, UI статистики, прогресса и `lengthTelemetry`.
- [ ] Промпты агента, Planner/Writer/Review/Reviser, confirmation и сообщения об успехе/ошибке: русский текст при `ru` без скрытой китайской ветки.
- [ ] Тесты round-trip (`create → save → reopen → revise → recover`), корректное восстановление и отмена задач, сохранение порядка write-lock/atomic commit.
- [ ] Тесты неизменности `zh/en`: эквивалентность счётчиков, сериализации и ключевых выходных артефактов.

**Gate 1:** создание книги/работы `ru` доступно через CLI и API; значение языка сохраняется через полный цикл, кириллица считается по правилам, `zh/en` проходят исходные тесты; отсутствуют молчаливые маршруты `ru → zh`. Здесь ещё не требуется полный русский Studio.

### Этап 2 — Все творческие режимы, поиск и доставка (P0/P1; зависит от 1)

**Работы:**
- [ ] Отдельно интегрировать и покрыть тестами long/short, сценарии, раскадровку, fanfic/spinoff/continuation/imitation, Play, interactive film, прогнозирование, импорт и перевод.
- [ ] Проверить правильную кодировку, названия, пути и ссылки в русских проектах на Windows; отличать отображаемый Unicode title от безопасного ID/имени файла; не применять транслитерацию к тексту автора.
- [ ] SQLite FTS5/BM25: тесты запросов в разных падежах, `е/ё`, составных имён, многословных терминов, заимствований. Сначала измерить recall; только после этого решать о стемминге/лемматизации. Исходники поиска остаются авторитетными.
- [ ] Провести тесты сегментации русского перевода, переводческого глоссария, повторного запуска, сверки сегментов и двунаправленного `ru ↔ en/zh`.
- [ ] Экспорт EPUB (`ru-RU` language metadata, кириллические оглавления/имена, читабельность), MD/TXT, интерактивные экспорты. Повторно открыть и проверить файл, а не только факт создания.
- [ ] Проверить изображения и обложки: русские заголовки и текстовые метаданные; не заявлять надёжный рендер надписей на самой картинке без отдельной проверки.

**Gate 2:** каждая строка Coverage Matrix имеет хотя бы один воспроизводимый русский end-to-end тест либо документированное ограничение/блокер; импорт/экспорт не теряет символы, `е/ё`, метаданные и состояние.

### Этап 3 — Методика русской литературы и редактура (P1; зависит от 1, удобно после 2)

**Работы:**
- [ ] Создать русские авторские Skills/refs: роман, рассказ, сценарий, интерактивный диалог, редактура, семантическая очистка, стилистическое редактирование и художественный перевод. Сохранять исходные встроенные Skills и их идентификаторы; развивать как override/дополнение.
- [ ] Правила для падежей и согласования, видов глагола, пунктуации прямой речи, диалогов с тире, регистра, `ё/е`, речевых характеристик персонажей и стилистической связности.
- [ ] Антишаблонность: избегать калькирования, пустой патетики, клишированных связок и пояснений вместо действия. Не использовать механические чёрные списки слов или бессмысленное «детектирование ИИ».
- [ ] Контроль качества сюжета: POV, таймлайн, достоверность персонажей, арки, факты мира, незакрытые обещания, цель сцены, отличие критической ошибки от вкусового замечания.
- [ ] Собрать небольшой **авторский/лицензионно чистый** проверочный корпус нескольких жанров, включая отрицательные и спорные примеры; контрольные примеры отделены от разрабатываемых Skill-инструкций.
- [ ] Сравнить результаты одинаковых задач до/после адаптации (одна модель и настройки, повторные прогоны), оценить по рубрике 1–5: грамматика, естественность диалогов, стиль, сюжетная непротиворечивость, следование ТЗ; сохранить конкретные фрагменты-обоснования.
- [ ] Внести русские правила редактуры так, чтобы они не меняли факты, голос автора или жанр без его запроса.

**Gate 3:** Skills подключаются штатно и проходят экспертный ручной просмотр примеров; критические ошибки канона — 0 в контрольном сценарии, остальные оценки и ограничения честно задокументированы. Качество генерации не объявлять «улучшенным» без сравнительных данных.

### Этап 4 — Русский интерфейс и UX (P1; зависит от 1–2)

**Работы:**
- [ ] Перевести Studio на расширяемую схему ключей `locales/zh`, `en`, `ru` (конкретный формат выбрать по фактическим ограничениям React/Vite). Сохранить текущие ключи и совместимость при постепенном переносе `tr(zh,en)`.
- [ ] Перевести навигацию, Studio Chat, карточки подтверждения, проекты, редактор, аналитические панели, переводчик, Play, интерактивное кино, прогнозы, настройки моделей, статусы длительных задач, ошибки API.
- [ ] Отдельно локализовать CLI, TUI, помощь, onboarding, `doctor`, вывод диагностики и непредвиденные ошибки; не переводить исполняемый синтаксис команд.
- [ ] Переключатель UI локали без изменения языка текущего произведения; язык новой книги — отдельное поле; посессионная инструкция пользователю не должна менять канон.

**Gate 4:** русский интерфейс проходит маршруты «первый запуск → создание книги → редактирование → экспорт → настройка модели» без непереведённых критических элементов и без изменения `contentLanguage`.

### Этап 5 — Сквозная приёмка, регрессии и эксплуатация (P0/P1; зависит от 0–4)

**Автоматические тесты:**
- [ ] `pnpm install --frozen-lockfile`, `pnpm build`, `pnpm -r typecheck`, `pnpm test`, `pnpm test:flows`, Studio E2E и проверки pack-артефактов.
- [ ] CI Windows/Linux × Node 22/24; pin pnpm на согласованной версии. Нет случайного обновления зависимостей при локализации.
- [ ] Property-/table-driven тесты BCP47 нормализации; `ru/en/zh` без silent fallback; round-trip схем/файлов/сессий/экспорта; проверка недопустимых языков.
- [ ] Таблица русского подсчёта: «Мальчик медленно открыл дверь» = 4 слова; `по-русски`, `из-за`, `50-летний`, `т. д.`, кавычки «ёлочки», `ё/е`, дефисы/тире, Unicode NBSP, Markdown frontmatter. Точное правило для составных слов сначала утверждается в тестовом контракте.
- [ ] Обратная совместимость архивов `zh/en`, миграции из 1.x в 2.x, восстановление после прерывания, корректность конвейера изменения главы, атомарная запись, безопасная конкуренция задач.
- [ ] Negative tests на плохой model output, timeout, отмену, неполное действие, отсутствующий API-ключ и модель; никаких заявлений об успешном сохранении без фактического file/result.

**С реальной LLM (отдельный необязательный по ключам, но обязательный для заявления о литературном качестве этап):**
- [ ] Изолированный тестовый русский роман: три **последовательные** главы с повторяющимися героями, сюжетными ограничениями, прогнозом, редактурой, закрытием одной завязки и сохранением другой.
- [ ] Возобновить после перезапуска Studio; проверить continuity/state и журнал действий; экспортировать EPUB и повторно распаковать/прочитать метаданные и главы.
- [ ] Отдельные короткая проза, сценарий, Play (минимум 2 перехода), interactive film (минимум 2 ветки), перевод с глоссарием, импорт русского текста.
- [ ] Сохранить модель, версию, endpoint **без секрета**, параметры, токены и затраты, входное ТЗ, текст, результаты проверок и известные отклонения. Внешние API/выгрузка текстов — только для искусственных/разрешённых примеров.
- [ ] Ручной протокол оценки художественных свойств; отсутствие доступа к модели/ключам = `NOT VERIFIED`, а не PASS.

**Gate 5:** все обязательные тесты PASS, исключения перечислены как блокеры, демонстрационные проекты воспроизводимы; ни один FAIL/SKIP не скрыт общим числом «тесты прошли».

## 6. Зависимости, приоритет и инкрементальные поставки

- **P0 (блокирует остальных):** Этап 0 → языковые схемы и отсутствие silent fallback → `ru_words` → round-trip данных → универсальные контракты → сквозной экспорт/память.
- **P1 (после основы):** творческие режимы и их E2E; качественные Skills; русский UI; ручная оценка качества.
- **P2 (после MVP):** углублённая морфология поиска, стиль-профили российских платформ, дополнительные проверки типографики и доступности, расширенный релизный UX.
- Рабочий MVP после Этапа 2: можно **создать и продолжить** русскую книгу через CLI/API, корректно сохранить/восстановить и экспортировать. Это ещё не «полная русификация».
- Для больших переделок UI и Skills разрешены параллельные ветки **после** стабилизации общих контрактов. Слияние — только после зелёных тестов.
- Максимально небольшие PR по одной ответственности: схема/нормализация, счётчики, writers, режимы, экспорт, словари, UX и т.д. При расхождениях с upstream сначала обновить карту, затем править.
- Не менять исходную китайскую/английскую настройку по умолчанию существующим пользователям.

## 7. Обязательный протокол отчётности по каждому этапу

Отчёт в PR/`docs/`:
1. Контрольная исходная и результирующая SHA, список изменённых файлов и связь с задачами Coverage Matrix.
2. Что теперь действительно работает; что ещё не поддержано, включая дополнительные языковые ветки и UI.
3. Команды проверок, количество PASS/FAIL/SKIP, среда (OS/Node/pnpm), ссылка на CI.
4. Скриншоты/артефакты/выходные файлы там, где требуется подтверждение интерфейса или экспорта.
5. Новый риск/регрессия и способ отката; обработка миграции/данных; статус лицензии/секретов.
6. Статус Gate: **PASS**, **PARTIAL**, **BLOCKED** или **NOT VERIFIED**, без завышения результата.

### Definition of Done всего проекта

- [ ] Все строки Coverage Matrix имеют реализованный `ru` и доказательство, либо явно принятый несрочный follow-up **за пределами заявленной полной поддержки**.
- [ ] Нет случайной подмены `ru` на `zh` или `en` в записи данных, агенте, пользовательских сообщениях и экспорте.
- [ ] `zh/en` обратная совместимость подтверждена тестами.
- [ ] Реальные рукописи остаются приватными, ключи не попадают в журнал/репозиторий, миграции восстановимы.
- [ ] Автотесты, интеграционные тесты и ручной литературный smoke-test имеют воспроизводимые отчёты.
- [ ] Независимый релиз и обновления upstream не нарушают AGPL и не публикуют пакеты оригинального автора.

## 8. Риски и способы снижения

| Риск | Последствие | Решение |
|---|---|---|
| Размноженные `zh/en` проверки | Частичная локализация и скрытая китайская ветка | Реестр точек входа, типизированные маршруты, тест на неизвестный язык |
| Изменение схем и state | Старые книги не открываются, ломаются возвраты | Снимки/migration dry-run/откат, золотые фикстуры `zh/en` |
| Ошибочная сегментация русского | Неадекватная длина, бесконечная дописка | `ru_words` со стабильным контрактом и измерением во всех этапах |
| Слабый поиск по русским падежам | Агент упускает события/персонажей | Recall-тесты на искусственном корпусе, опциональная лемматизация лишь при пользу |
| Машинный перевод интерфейса | Некорректные действия и вводящие в заблуждение ошибки | Отдельный QA по контексту, параметрам, plural rules, UI E2E |
| Skills меняют голос или сюжет | Потеря авторского намерения | Связанный канон, проверка минимальной редакции, авторские рубрики |
| Модели по-разному пишут русский | Нестабильное качество | Фиксация модели/настроек/семплов, сравнение нескольких прогонов |
| Обновление upstream | Конфликты с локальными патчами | Малые PR, ADR, регулярный тестовый rebase/merge |
| Чужой npm release workflow | Случайный выпуск `@actalk/*` | Заблокировать публикацию на этапе 0 до независимого release |
| Утечка рукописей/ключей | Риск конфиденциальности | Искусственные тестовые данные, чистые лог/trace, явный выбор provider |
| Русские пути на Windows | Ошибки файлов/архивов | Unicode round-trip и отдельно ASCII IDs от отображаемых названий |

## 9. Первые конкретные задачи после утверждения v2.0

1. Запустить Stage 0: снять baseline, зафиксировать версии/SHA и результаты существующих проверок.
2. Создать `docs/LANGUAGE_COVERAGE.md` и машинно проверяемый список языковых контрактов (`zh/en/ru`) по компонентам.
3. Создать оригинальные фикстуры `ru/en/zh` и тесты будущего поведения, которые на текущем коде демонстрируют нужные изменения.
4. Обезопасить релиз GitHub Actions, не публикуя ничего.
5. Начать Этап 1 в узких последовательных ветках после закрытия Gate 0.

**Критерий остановки:** если обнаружено расхождение с обновившимся upstream, проблема миграции пользовательских данных или угроза публикации исходных пакетов — сначала исправить архитектурный план и тесты, затем продолжить код.
